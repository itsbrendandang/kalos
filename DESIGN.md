# Kalos design system

The engine portal and `kalos-web` are two surfaces of one product. The complete
source of truth lives in `kalos-web/DESIGN.md`; this file records the shared
contract for the Python repository.

## Memorable thing

**Serious scientific intelligence that feels calm, trustworthy, and easy to act on.**

## Shared direction

- Botanical precision: warm mineral surfaces, deep evergreen structure,
  emerald action/progress, and clay exploration/uncertainty.
- Evidence before recommendation. Always expose reliability and uncertainty.
- One primary next action per screen.
- Prepare → analyze → decide → run → learn is the product workflow.
- Satoshi for product language where available; JetBrains Mono only for values.
- Minimum 44px controls, visible focus, semantic status labels, and responsive
  layouts designed for mobile rather than merely stacked.

## Core tokens

- Canvas `#F1F2EB`
- Surface `#FCFDF9`
- Ink `#14231C`
- Muted ink `#59685F`
- Border `#DDE3DA`
- Evergreen `#13271F`
- Emerald `#159A6E`, hover `#0E7653`, soft `#DFF1E9`
- Clay `#B96F2B`, soft `#F7E9D7`

## Rules

- No generic dashboard mosaics, purple gradients, decorative blobs, or tiny
  low-contrast instructions.
- Demo, simulated, projected, and live content must be labeled.
- Cards represent real objects or interactions, not arbitrary page sections.
- Offline/local status must be stated plainly.
- All new UI work must also satisfy the detailed system in
  `kalos-web/DESIGN.md`.
